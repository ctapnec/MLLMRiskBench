# Campaign demonstration and subsequent workstation archive

Agreed sequence, 14 September 2026. This is a migration plan, not a claim that
an archive transfer or workstation execution has already passed acceptance.

1. Finish the existing approved collection, output-specific judging and result
   reconciliation on the rig. Retain quota waits and unresolved outcomes honestly.
2. Verify and document small local and hosted campaigns configured through Build.
   Use the same retained inputs, seed and replay conditions for comparison.
   Keep demonstration results separate from the thesis study populations.
3. Let the operator reproduce those small examples using the documented UI flow.
4. Transfer the completed experiment archive and console state to Windows only
   after path relocation, media, statistics and export acceptance succeeds.

## Small UI demonstrations

The existing [UI walkthrough](UI_CAMPAIGN_WALKTHROUGH.md) describes the controls.
The remaining acceptance must provide concrete installed-model and corpus
choices, a small input count, sampling seed, effective generation settings,
local answer retries, zero hosted answer retries and bounded transport retries.
Forecast the hosted example and its required judging before execution. Use
saved local inputs for the hosted example so text and image content genuinely
match, rather than assuming independently entered limits select identical data.
Verify collection, Jobs ownership, output-specific local and Haiku judging,
Stats, costs and exports. Saving or reviewing the definition must make no calls.
The operator walkthrough must distinguish those actions from launching it.

No additional broad local campaign is approved by this demonstration plan.
Do not silently spend the remaining purses on a new experiment. Retained
human-review preparation is separate from generating demonstration outputs.

## Archive contents and acceptance

Keep the console SQLite data, selected and historical responses, attempts,
judgments, explicit replacement relationships, generation conditions, usage and
cost records, analysis outputs and the referenced prompt media. Preserve source
and licensing attribution. Keep enough source/configuration information to
explain and reproduce the studies on a suitable execution machine.

Do not copy model weights, runtime virtual environments, caches, transport
bundles or provider secrets merely to browse completed results. Framework and
GPU installations are not required for archive viewing, but local inference
still needs suitable hardware and its serving/runtime environment.

Take a consistent database backup and retain the rig copy until the workstation
copy has passed acceptance. Rewrite only installation locators through an
explicit relocation map; preserve scientific identities, output contents and
accounting. Test both campaigns, their selected generation conditions, media,
matched comparisons, charts, costs, downloads and human-review state. Historical
external jobs must remain historical, not falsely appear as running Windows
processes. Opening the archive must not resume paid work or model downloads.

Human ratings, if later collected on Windows, must remain real independent
records with the applicable study arrangements. Automated tests must continue
to use separate storage. Only after these checks should the rig be retired from
the workflow; no rig data is scheduled for deletion by this plan.
